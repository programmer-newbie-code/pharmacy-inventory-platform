# Project Scaffold & CI Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the `pharmacy-inventory-platform` Flutter project skeleton (layered
architecture, drift schema for all 8 v1 tables, i18n toolchain, one real feature slice
end-to-end) with a green GitHub Actions CI pipeline enforcing 80% test coverage, then
open the private GitHub repo and merge this scaffold through a reviewed PR.

**Architecture:** `lib/domain` (pure Dart business logic), `lib/data` (drift database),
`lib/features/home` (first screen, proves the stack wires together), `lib/core`
(reserved for shared utils — empty until a second feature needs it, per YAGNI). Full
schema from the design spec is created now since it's already fully specified and
future feature plans build on top of it rather than re-deriving it.

**Tech Stack:** Flutter (stable channel), `drift` + `sqlite3_flutter_libs` (SQLite),
`flutter_riverpod` (state), `flutter_localizations` + ARB-based l10n (en/id),
GitHub Actions CI.

**Out of scope for this plan (separate future plans, per the design spec's section
list):** login/auth screens and role permission enforcement (spec §5), POS/sales
screens and FEFO batch selection (spec §3, §5), min-sell-price warning (spec §4),
expiry/low-stock notification screens (spec §6), backup/restore to Drive+local (spec
§7), Excel export (spec §8), barcode scanning UI (spec §2). This plan only lays the
foundation those features are built on: the full schema, the layered structure, i18n,
and a working CI gate.

**Environment note:** Flutter SDK is not installed in this dev environment. Every step
below is verified via GitHub Actions (which provisions Flutter itself via
`subosito/flutter-action`), not locally. Platform folders (`android/`, `windows/`) are
**not** committed — CI regenerates them each run via `flutter create --platforms=...`
on the existing project, which is the documented-safe way to add platform support
without touching already-existing `lib/`/`pubspec.yaml`. This avoids hand-writing
Gradle/CMake boilerplate that can't be verified locally. Revisit once a native
customization (app icon, camera permission, code signing) requires committing those
folders — noted as a `ponytail:` comment in `.gitignore`.

```dart
/// Converts a quantity expressed in a product's purchase unit (e.g. "strip")
/// into its base unit (e.g. "tablet") using the product's conversion factor.
int convertToBaseUnit({
  required int quantityInPurchaseUnit,
  required int unitsPerPurchaseUnit,
}) {
  if (unitsPerPurchaseUnit <= 0) {
    throw ArgumentError.value(
      unitsPerPurchaseUnit,
      'unitsPerPurchaseUnit',
      'must be greater than zero',
    );
  }
  return quantityInPurchaseUnit * unitsPerPurchaseUnit;
}
```

```yaml
name: CI

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  analyze-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with:
          channel: stable
      - name: Backfill platform folders
        run: flutter create --platforms=android --org com.programmernewbiecode .
      - run: flutter pub get
      - name: Generate drift code
        run: dart run build_runner build --delete-conflicting-outputs
      - run: flutter analyze
      - run: flutter test --coverage
      - name: Enforce 80% line coverage
        run: |
          sudo apt-get update && sudo apt-get install -y lcov
          lcov --remove coverage/lcov.info '**/*.g.dart' -o coverage/lcov_filtered.info
          lcov --summary coverage/lcov_filtered.info
          COVERAGE=$(lcov --summary coverage/lcov_filtered.info | grep -Eo 'lines\.*: [0-9.]+%' | grep -Eo '[0-9.]+')
          echo "Line coverage: $COVERAGE%"
          awk -v cov="$COVERAGE" 'BEGIN { if (cov + 0 < 80) { print "Coverage below 80%"; exit 1 } }'

  build-windows:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with:
          channel: stable
      - name: Backfill platform folders
        run: flutter create --platforms=windows --org com.programmernewbiecode .
      - run: flutter pub get
      - name: Generate drift code
        run: dart run build_runner build --delete-conflicting-outputs
      - run: flutter build windows --release

  build-android:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with:
          channel: stable
      - name: Backfill platform folders

      - run: flutter pub get
      - name: Generate drift code
        run: dart run build_runner build --delete-conflicting-outputs
      - run: flutter build apk --release
```
