# Release v1.8.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans.
> Steps use checkbox (`- [ ]`) syntax.

**Spec:** [`2026-08-13-release-v1-8-0.md`](../specs/2026-08-13-release-v1-8-0.md)

**Goal:** Publish `v1.8.0` from green `main` and restore `CHANGELOG.md` as an
accurate record.

**Architecture:** No code change. CI derives the version from the tag, so the
release is an annotated tag plus documentation.

**Tech Stack:** git tags, GitHub Actions, GitHub Releases.

---

## Critical constraint

`docs/release/RELEASE_CHECKLIST.md`: **do not edit `pubspec.yaml`.** The
"Auto-Inject Dynamic Version" step in `.github/workflows/ci.yml` writes
`version: <tag-without-v>+<run-number>` during the build. Editing the file by
hand would fight that automation. The historical `chore: bump version` commits
predate it.

## Task 1: Restore the changelog

**Files:** modify `CHANGELOG.md`.

- [ ] List released tags: `git tag --sort=-v:refname`.
- [ ] For each missing version from `1.4.0` to `1.7.0`, read the PRs merged in
  that range (`git log v1.3.5..v1.4.0 --oneline --no-merges`, and so on) and
  write user-facing entries. Describe the outcome a pharmacist notices, not the
  commit subject. Match the existing terse style: a short bulleted list per
  version, no PR numbers.
- [ ] Add the `1.8.0` entry from the 22 user-visible commits in
  `v1.7.0..origin/main`. Lead with the logout fix, since that is the most
  severe.
- [ ] Confirm `git diff --name-only` shows only `CHANGELOG.md` for this task,
  and in particular **not** `pubspec.yaml`.
- [ ] Commit: `docs(changelog): record 1.4.0 through 1.8.0`.

## Task 2: Record the release in the handoff

**Files:** modify `docs/superpowers/status/current-roadmap.md`.

- [ ] Set **Next increment** to the release, replacing the localization slice 6
  entry. A stale "next increment" is what causes duplicated or wrong work
  across sessions.
- [ ] Update the **Release automation** row: 40 commits were unreleased at
  `503ce3d`; state that `v1.8.0` is the increment closing that gap.
- [ ] Record that manual smoke testing is **not** performed in this environment
  and remains an owner action before distributing artifacts.
- [ ] Commit: `docs(roadmap): set release v1.8.0 as the next increment`.

## Task 3: Ship the documentation through a PR

- [ ] Push the branch and open a PR describing the release rationale and the
  unreleased-commit evidence.
- [ ] Confirm every required check is green. Documentation-only changes skip the
  Flutter matrix because of the path filter added in #158, so expect
  `Classify Changed Paths`, secret scan, and signature verification only.
- [ ] Squash merge, then confirm `main` is green.

## Task 4: Tag the release

**Only after Task 3 is merged and main CI is green.**

- [ ] Re-read the target commit's CI status; tag only a commit with a green run:
  ```bash
  gh run list --branch main --limit 1 --json headSha,conclusion
  ```
- [ ] Create the annotated tag on that exact commit:
  ```bash
  git tag -a v1.8.0 -m "Release v1.8.0"
  git push origin v1.8.0
  ```
- [ ] Do **not** create a bump commit.

## Task 5: Verify the published release

- [ ] Watch the tag pipeline: `gh run watch <run-id> --exit-status`.
- [ ] Confirm `analyze-and-test`, `build-windows`, `build-android`, secret scan,
  and signature verification all pass, and that `create-release` ran rather than
  being skipped.
- [ ] Confirm the release and its assets:
  ```bash
  gh release view v1.8.0 --json tagName,assets --jq '{tagName, assets:[.assets[].name]}'
  ```
- [ ] Expect a Windows package and an Android APK/AAB. If an asset is missing,
  read the `create-release` log rather than assuming success.
- [ ] If the pipeline is red, delete the tag locally and remotely, fix forward on
  a branch, and re-tag. Never leave a published release built from a red
  pipeline.

## Task 6: Close the loop

- [ ] Update `docs/superpowers/status/current-roadmap.md` with the released tag,
  the verifying run id, and the artifact names.
- [ ] Set the next increment to localization slice 6, the remaining
  non-blocked work.
- [ ] PR, green CI, merge, verify main.

## Stop conditions

- Tag CI red: do not publish; fix forward and re-tag.
- Any required check missing rather than passing: investigate before merging.
- A change appears in `pubspec.yaml`: revert it, the version is tag-derived.
